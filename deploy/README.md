# Deploying to a LEMP server

Target layout — the repo lives at `/var/www/html/glovel`, and nginx serves the
built site from `dist/` inside it:

```
/var/www/html/glovel/
├── dist/                 <- nginx document root (generated by npm run build)
├── public/               <- CMS writes here (content + uploads)
├── content/              <- CMS master copy
├── server/cms-server.mjs <- CMS API, runs under systemd on :8787
├── src/  scripts/  package.json
└── assets-source/        <- archived original images, never served
```

You do **not** need PHP or MySQL for this site. It is a static build plus one
small Node service. The "M" and "P" of your LEMP stack can stay installed and
unused.

---

## 1. Install Node

The build needs Node 20 or newer (`sharp` and the build scripts rely on it).

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v
```

## 2. Get the code onto the server

```bash
sudo mkdir -p /var/www/html/glovel
sudo chown -R $USER:$USER /var/www/html/glovel
# then upload the project (git clone, rsync, scp — whichever you use)
cd /var/www/html/glovel
```

If you rsync from your machine, exclude the heavy folders — `dist` and
`node_modules` get regenerated on the server, and `assets-source` is only needed
if you plan to re-encode images there:

```bash
rsync -avz --exclude node_modules --exclude dist \
      ./ user@server:/var/www/html/glovel/
```

## 3. Set your real domain before building

The canonical URLs, sitemap and JSON-LD are all generated from one constant.
Edit `src/seo/siteConfig.js`:

```js
export const SITE_URL = 'https://www.safetymatches.in';   // <- your live domain
```

Getting this wrong is not cosmetic: every canonical tag would point at the wrong
host and the pages may not rank at all.

## 4. Build

```bash
cd /var/www/html/glovel
npm ci
npm run build
```

This runs Vite, then generates `sitemap.xml` and the twelve prerendered route
folders. You should see:

```
sitemap.xml  12 urls
prerender    12 routes
base url     https://www.safetymatches.in
```

If you added new images through the CMS since the last build, also run
`npm run images` first to generate their WebP variants.

## 5. nginx

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/glovel
sudo nano /etc/nginx/sites-available/glovel     # set server_name + paths
sudo ln -s /etc/nginx/sites-available/glovel /etc/nginx/sites-enabled/glovel
sudo rm -f /etc/nginx/sites-enabled/default     # if it would otherwise win
sudo nginx -t && sudo systemctl reload nginx
```

The one line that matters most is in that config:

```nginx
location / {
    try_files $uri $uri/index.html /index.html;
}
```

A normal SPA config rewrites everything to `/index.html`. That would shadow the
prerendered per-route files and put the homepage's title, description and
canonical on all twelve URLs — undoing the SEO work. `$uri/index.html` must come
before the fallback.

## 6. Permissions

nginx reads `dist/` and `public/`; the CMS service writes to three paths.

```bash
sudo chown -R www-data:www-data /var/www/html/glovel
sudo find /var/www/html/glovel -type d -exec chmod 755 {} \;
sudo find /var/www/html/glovel -type f -exec chmod 644 {} \;
```

## 7. CMS service (optional)

Skip this whole step if you would rather edit content locally and redeploy.

```bash
sudo cp deploy/glovel-cms.service /etc/systemd/system/
sudo nano /etc/systemd/system/glovel-cms.service    # SET CMS_PASSWORD
sudo systemctl daemon-reload
sudo systemctl enable --now glovel-cms
systemctl status glovel-cms
```

**Change `CMS_PASSWORD`.** The fallback in the code is `glovel-admin`, which is
in the repo and therefore public. Anyone who finds `/admin` could rewrite your
site content with it.

## 8. HTTPS

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d safetymatches.in -d www.safetymatches.in
```

Do this before using `/admin`: the CMS password is sent in a request header and
would otherwise cross the network in plaintext.

## 9. Verify

Each route must return **its own** title, not the homepage's:

```bash
for r in "" our-products household-matches wax-matches contact-us; do
  printf "%-20s " "/$r"
  curl -s "https://safetymatches.in/$r" | grep -o '<title>[^<]*</title>'
done
```

Twelve different titles means routing is correct. Twelve identical ones means
`try_files` is wrong — recheck step 5.

Also confirm:

```bash
curl -sI https://safetymatches.in/assets/images/products/household/household-match-01-400.webp | head -1
curl -s  https://safetymatches.in/sitemap.xml | head -5
curl -s  https://safetymatches.in/robots.txt
curl -s  https://safetymatches.in/content/site-content.json | head -c 120
```

Then in Google Search Console: add the property and submit
`https://safetymatches.in/sitemap.xml`.

## Updating later

**Content edited through /admin** — live immediately. nginx serves
`/content/` and `/assets/images/` straight from `public/`, which is where the
CMS writes.

**Code or SEO text changed** — rebuild:

```bash
cd /var/www/html/glovel && git pull && npm ci && npm run build
sudo systemctl reload nginx
```

**New images uploaded through /admin** — they work right away at full size, but
have no WebP variants until you run:

```bash
npm run images        # generate variants for the new files
npm run build         # bundle the updated manifest
```

## Troubleshooting

| Symptom | Cause |
|---|---|
| Every URL shows the homepage title | `try_files` missing `$uri/index.html` (step 5) |
| Deep links 404 on refresh | `try_files` missing the `/index.html` fallback |
| CMS saves succeed but the site doesn't change | The `/content/` alias block is missing, so nginx is serving the stale copy baked into `dist/` |
| Image upload fails with 413 | `client_max_body_size` too low — uploads are base64 and inflate ~33% |
| `/admin` saves return 401 | `CMS_PASSWORD` in the systemd unit doesn't match what you typed |
| Images 404 | You ran `npm run images -- --prune` but not `npm run build`, so `dist/` is stale |
| Contact / RFQ says email not configured | Set `SMTP_PASS` in `glovel-cms.service` to a Google Workspace App Password for `ecommerce@rajexim.co.in`, then `systemctl daemon-reload && systemctl restart glovel-cms` |
| Contact / RFQ mail not arriving | Confirm App Password for the From mailbox, that `export@glovel.in` exists, and check `journalctl -u glovel-cms -n 50` |

## Contact / RFQ email (Google Workspace)

Contact and RFQ forms POST to `/api/cms/contact`. The CMS service sends mail via Gmail SMTP:

| Setting | Value |
|---|---|
| From | `ecommerce@rajexim.co.in` |
| To | `sales@glovel.in`, `export@glovel.in` |
| Reply-To | visitor’s email |

**One-time Google setup**

1. For `ecommerce@rajexim.co.in`, enable 2-Step Verification.
2. Create an App Password (Google Account → Security → App passwords).
3. Put that 16-character password in the systemd unit as `SMTP_PASS` **with no spaces**
   (Google shows `xxxx xxxx xxxx xxxx` — enter `xxxxxxxxxxxxxxx`). Values with spaces break
   systemd `Environment=` lines.

```bash
sudo nano /etc/systemd/system/glovel-cms.service
# set SMTP_USER / MAIL_FROM=ecommerce@rajexim.co.in
# set SMTP_PASS=xxxxxxxxxxxxxxxx   # NO SPACES
sudo systemctl daemon-reload
sudo systemctl restart glovel-cms
curl -s http://127.0.0.1:8787/api/cms/health
# expect: "mailConfigured": true
```

**CMS admin password:** whatever is set as `CMS_PASSWORD` in the same unit (not the default
`glovel-admin` hint unless that is still the value).
